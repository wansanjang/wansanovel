# Day 1 (Astro)

일을 하면서 AI를 열심히 쓰고 있다. 남들처럼 클로드 코드로 뭔가를 쫙쫙 뽑아내지는 못하지만, Gemini가 사용량 다 되었다는 이야기를 2~3일에 한 번씩은 보고 있으니, 나름 열심히 쓰고 있는 것 같다. (pro 활용 중)

바이브 코딩, 클로드 코드, 안티 그래비티.. 쓰레드에서 보기는 많이 봤지만, 사실 뭔지 잘 모른다. 토큰은 버스 토큰의 개념과 잘 구별하지 못한다. 대충 사용량 정도? 모뎀 시대 인터넷의 패킷 정도로 이해하고 있다. 근데, ai랑 이야기하다 보면 용기가 생긴다. 그래서 개인 홈페이지를 한 번 만들어 보기로 했다.

사실 디지털 비즈니스의 전선에 있으면서 ai와 관련된 것은 이론으로만 공부했다. 그래서 이론은 충분한데 실전을 제대로 못해봤다. 그렇다고 회사 제품에 테스트를 해볼 수도 없는 것이니- 뭐라도 해봐야겠다 싶었다. 그래서 생각한 것이 홈페이지이다. 전통적 문과적 사고 방식을 갖은 내가, 노코딩이라 하더라도 홈페이지를 만들어 볼 수 있을까? 일단 뭐라도 해보자는 생각으로 시작해 보았다.

그리고 AI와 친한 인간으로 살아남기 위한 몸부림의 일환으로. 홈페이지 만들기에 돌입하자 마자 어려운 말들이 쏟아지기 시작했다. 하나하나 뜯어다가 보면 안되는 것 없겠지. 

기술 스택의 선정 - 와 이 말부터 어렵다. 다행히도 워드프레스와 노션에는 이해가 있던 상황이다.

> 왜 워드프레스나 노션 연동형이 아니라 **Astro와 Vercel**인가? (압도적인 속도 Zero-JS로 구글 라이트하우스 100점 맞기 도전, 깃허브 푸시 한 번으로 끝나는 자동 배포 체계의 편리함)

제미나이는 이렇게 이야기해줬다. 아스트로는 차은우 소속 그룹이라는 것만 알았다. 구글 라이트 하우스에서 구글만 이해했다. 깃허브는 개발자 커뮤니티 정도로만 알고 있었고, 자동 배포라는 말은 편리해 보였다. 그래서 하나하나 검색하기 시작했다.

그전에 내가 이렇게 홈페이지를 만드는 과정을 기록으로 남기는 것이 유의미 할 지에 대한 고민부터 해봤다. 역시나 제미나에게 물어봤더니, 또 용기를 줬다.

- 답변
    
    Astro를 고민하시는 지금 시점은 탁월한 선택입니다. 웹 트렌드가 '무겁고 화려한 앱' 중심에서 다시 '본질에 집중한 초고속 웹페이지'로 회귀하고 있기 때문입니다.
    
    Astro가 도대체 무엇인지, 왜 지금 글로벌 테크 씬에서 주목받는지, 그리고 왜 본인 같은 성향의 사람에게 완벽한 무기가 되는지 명쾌하게 정리해 드릴게요.
    
    **1. Astro란 무엇인가? (개념)**
    Astro는 한 마디로 "콘텐츠 중심의 웹사이트를 만들기 위한 최신 초고속 정적 사이트 빌더(Static Site Builder)"입니다. 기존의 현대 웹 프레임워크(React, Next.js 등)는 사용자가 접속하면 브라우저에서 무거운 자바스크립트(JS) 코드를 실행하느라 첫 로딩이 느려지는 고질병이 있었습니다. 반면 Astro는 "Island Architecture(아일랜드 아키텍처)"라는 혁신적인 기술을 씁니다.
    
    - **Zero-JS (기본 상태):** 서버에서 코드를 빌드할 때 자바스크립트를 100% 걷어내고, 오직 순수한 HTML과 CSS만 남겨서 전 세계에 배포합니다. 이 때문에 속도가 빛처럼 빠릅니다.
    - **섬(Islands) 구조:** 웹사이트 전체는 가벼운 HTML이지만, 만약 상단 검색창이나 다크모드 버튼처럼 '실제 작동(Interactive)'이 필요한 부분만 자바스크립트 "섬"으로 지정해 그 부분만 동적으로 작동하게 만듭니다.
    
    **2. Astro의 핵심 경쟁사 비교**
    웹사이트를 만들 때 비교하게 되는 대표적인 경쟁 도구들과의 차이점입니다.
    
    - *(WordPress)**전 세계 웹의 40%를 차지하는 전통의 강자. PHP 기반의 CMS.**Astro가 압승.** 워드프레스는 무겁고 보안 취약점이 많아 유지보수가 귀찮습니다. Astro는 서버가 필요 없는 정적 배포라 해킹 위험이 제로에 가깝고 속도가 비교가 안 됩니다.
    - **Next.js (Vercel)** 현재 프론트엔드 생태계의 절대강자. 풀스택 프레임워크.**콘텐츠용으로는 Astro 우세.** Next.js는 '당근마켓'이나 '토스' 같은 복잡한 웹 서비스를 만들 때 최적입니다. 단순히 글을 보여주는 개인 홈페이지/블로그에는 필요 이상으로 무겁습니다.
    - **Hugo / Jekyll**전통적인 마크다운 기반 정적 사이트 생성기.**개발 확장성에서 Astro 우세.** Hugo는 Go 언어를, Jekyll은 Ruby 언어를 알아야 커스텀이 쉽습니다. 반면 Astro는 자바스크립트 기반이라 나중에 컴포넌트(React 등)를 붙이기가 훨씬 쉽습니다.
    
    **3. 왜 '나 같은 사람'에게 특히 좋은가?**
    본인의 역량(비즈니스, AX 자동화, 마켓 인사이트)과 성향을 고려했을 때, Astro는 다음과 같은 압도적인 이점을 줍니다.
    
    **① SEO, AEO, GEO 부문에서 '사기적인 점수' 획득**
    앞서 말씀드렸듯 Astro는 불필요한 자바스크립트 기름기를 쫙 뺀 **순수 HTML**을 뱉어냅니다. 구글 검색 로봇이나 ChatGPT/Perplexity 크롤러가 사이트를 방문했을 때, 복잡한 연산 필요 없이 텍스트 데이터를 가장 깨끗하고 빠르게 긁어갈 수 있습니다. "AI 엔진이 인용하기 가장 좋아하는 구조"를 바닥부터 기본 탑재하고 시작하는 셈입니다.
    
    **② 'AI 자동화(AX) 테크베드'로의 무한한 확장성**
    Astro는 기본적으로 자바스크립트/타입스크립트 생태계 위에 있습니다.
    지금은 마크다운 파일(`.md`)로 글을 직접 쓰지만, 나중에 본인이 다루는 **n8n 워크플로우를 고도화하여 "내가 노션에 글을 쓰면 -> n8n이 감지해서 -> Astro 코드로 변환해 -> GitHub에 자동 커밋"** 시켜버리는 파이프라인을 구축할 수도 있습니다. 템플릿의 소스코드가 매우 명확해서 자동화 봇(Bot)이 접근하기에 아주 좋습니다.
    
    **③ 완벽한 소유권과 '유지비 0원'**
    워드프레스는 매달 서버 호스팅 비가 나가고, 브런치는 내 도메인을 쓰지 못합니다. Astro로 빌드하여 Vercel에 올리면 트래픽이 폭발해도 평생 0원(무료)입니다. 또한 소스코드가 내 GitHub에 안전하게 아카이빙되므로 플랫폼의 변덕에 휘둘리지 않는 완벽한 독립 영토가 됩니다.
    
    **💡 한 줄 요약****"Next.js처럼 트렌디하고 확장성이 좋은데, 워드프레스보다 안전하고, 속도는 세상에서 가장 빠른 도구"**가 바로 Astro입니다. 코딩 테스트 겸 개인의 뇌(Second Brain)를 세상에 브랜딩하기 위한 도구로 이보다 적합한 스택은 현재 존재하지 않습니다. 자, 어떤가요? 이 영리한 프레임워크의 세계로 직접 한 발짝 들여놓아 보시겠어요?

> 질문: 깃허브에 아이디는 있어, 그러면 내가 아스트로를 쓰려면 깃허브를 어떻게 세팅해야 하고, 이 모델은 어떻게 돌아가는거냐? 그리고 아스트로로 홈페이지를 만들면 이걸 어떻게 퍼블리시하냐? (그래도 퍼블리시 정도는 안다.)
> 
- 답변:
    
    GitHub 계정이 이미 있으시다면 준비는 끝났습니다. 개발자들의 현대적인 웹 배포 방식(CI/CD)을 직접 경험해 보실 차례입니다.
    
    질문하신 세 가지 핵심 프로세스(**GitHub 세팅 ➡️ 구동 원리 ➡️ Vercel 퍼블리시**)를 개발 용어를 최소화하여 명쾌하게 정리해 드릴게요.
    
    ## 1. 1단계: GitHub 세팅하기 (클릭 한 번으로 끝)
    
    바닥부터 코딩하는 것이 아니기 때문에, 깃허브 세팅은 오픈소스 템플릿을 **내 창고(Repository)로 그대로 복사해 오는 과정**으로 시작합니다.
    
    1. 마음에 드는 Astro 템플릿의 GitHub 저장소 페이지(예: [Astro Paper](https://github.com/satnaing/astro-paper))에 접속합니다.
    2. 우측 상단의 **`Fork`** 버튼을 누릅니다.
    3. 내 GitHub 아이디 아래에 `내아이디/my-homepage` 같은 이름으로 저장소를 생성합니다.
    4. **끝입니다.** 이제 내 깃허브 계정에 홈페이지의 모든 소스 코드가 복사되어 들어왔습니다.
    
    ## 2. 2단계: 이 모델은 대체 어떻게 돌아가는가? (구동 원리)
    
    전통적인 웹사이트(워드프레스 등)와 Astro 모델의 결정적인 차이는 "컴퓨터(서버)가 언제 일을 하느냐"에 있습니다.
    
    `[내 컴퓨터/GitHub] ➡️ ➡️ ➡️ (빌드/배포) ➡️ ➡️ ➡️ [Vercel CDN 글로벌 서버]
    (마크다운 글 작성)       (Astro가 HTML로 굽기)         (사용자는 0초 만에 HTML 읽음)`
    
    - **워드프레스 방식:** 사용자가 내 홈피 주소를 누르면, 그 순간 서버가 데이터베이스(DB)에서 글을 찾고 화면을 그려서 사용자에게 전달합니다. (접속자가 많으면 느려지고, 서버가 켜져 있어야 하므로 돈이 듭니다.)
    - **Astro 방식 (정적 사이트 생성 - SSG):**
        - 내가 마크다운(`.md`) 파일로 글을 쓰고 GitHub에 올리면, Astro라는 기계가 그 글들을 미리 싹 모아서 **지극히 가볍고 완벽한 '공장제 HTML 파일들'로 미리 구워버립니다(Build).**
        - 사용자가 접속하면 이미 다 만들어진 HTML 파일만 툭 던져주기 때문에 **로딩 속도가 0.1초** 수준으로 빠르고, 서버가 실시간으로 연산할 필요가 없어 **비용이 0원**이 됩니다. AI 크롤러들이 이 미리 구워진 HTML 텍스트를 가장 좋아합니다.
    
    ## 3. 3단계: Vercel로 퍼블리시(배포)하는 방법
    
    이제 깃허브에 있는 소스 코드를 전 세계 사람들이 볼 수 있도록 인터넷에 띄우는(Publish) 과정입니다. 클릭 3번이면 끝납니다.
    
    1. **Vercel 로그인:** [Vercel 홈페이지](https://vercel.com/)에 가서 `Continue with GitHub`를 눌러 내 깃허브 계정으로 로그인합니다.
    2. **프로젝트 가져오기:** 대시보드에서 `Add New` ➡️ `Project`를 누르면, 내 깃허브에 있는 창고들이 쭉 뜹니다. 방금 Fork 해온 템플릿 창고 옆의 **`Import`** 버튼을 누릅니다.
    3. **배포(Deploy):** 세팅을 건드릴 필요 없이 하단의 **`Deploy`** 버튼을 누릅니다.
    4. **완성:** 약 1~2분 동안 Vercel이 Astro 코드를 HTML로 굽는 과정을 거친 후, 폭죽이 터지며 `[https://내이름.vercel.app](https://내이름.vercel.app)` 이라는 전 세계 라이브 주소를 만들어줍니다.

    ## 1. 깃허브 이전의 시대: "코드를 나누는 게 너무 고통스럽다"
    
    깃허브가 등장하기 전(2000년대 중반)에도 **소스포지(SourceForge)** 같은 오픈소스 공유 사이트가 있었습니다. 하지만 당시의 협업은 지금과 비교하면 무척 비효율적이었습니다.
    
    - **중앙 집중식의 한계:** 당시 주로 쓰던 SVN(Subversion)은 중앙 서버 시스템이었습니다. 메인 코드를 수정하려면 권한이 있는 소수의 관리자만 가능했고, 일반 개발자는 접근하기 어려웠습니다.
    - **이메일로 오가던 패치:** 오픈소스에 기여하고 싶다면, 코드를 수정한 뒤 그 변경 사항(Patch 파일)을 메인 관리자에게 **이메일**로 보내고 무작정 반영해 주기를 기다려야 했습니다.
    - **리누스 토르발스의 Git 개발:** 이 답답함을 참지 못한 리눅스의 창시자 리누스 토르발스가 2005년, 분산형 버전 관리 시스템인 **Git**을 직접 개발하게 됩니다.
    
    ## 2. 깃허브의 초창기 (2007~2008): "개발자들을 위한 SNS"
    
    2007년 말, 톰 프레스턴베르너(Tom Preston-Werner), 크리스 완스트래스(Chris Wanstrath), 피제이 하이엣(PJ Hyett) 세 명의 개발자가 모여 Git을 기반으로 한 웹 플랫폼을 만들기 시작했고, 2008년 4월 공식 출시했습니다. 이들의 초기 슬로건은 "Social Coding(소셜 코딩)"이었습니다.
    
    ### 💡 오픈소스 역사를 바꾼 핵심 혁신: Pull Request (PR)
    
    깃허브가 개발자들을 열광시킨 핵심은 Git의 기능을 웹 UI로 극대화한 '포크(Fork)'와 '풀 리퀘스트(Pull Request)'의 발명이었습니다.
    
    1. 남의 코드를 내 저장소로 그대로 복사해 와서(**Fork**)
    2. 내 마음대로 수정하거나 기능을 개발한 뒤,
    3. 원작자에게 "내가 코드를 이렇게 고쳤는데 네 프로젝트에 반영해 줄래?"라고 요청(**Pull Request**)하는 시스템이었습니다.
    
    이 과정이 웹상에서 완벽하게 시각화되고, 코드 라인별로 댓글을 달아 토론할 수 있게 되면서 오픈소스 생태계가 폭발적으로 성장하기 시작했습니다. Ruby on Rails, Reddit, Twitter 같은 대형 프로젝트들이 이 시기에 대거 깃허브로 둥지를 옮겼습니다.
    
    ## 3. 성장과 플랫폼화 (2010년대): 개발자의 이력서가 되다
    
    깃허브는 단순한 코드 저장소에서 개발자들의 '문화 공간'이자 '글로벌 서비스'로 체급을 키우기 시작합니다.
    
    - **잔디 심기 (Contribution Graph):** 개발자가 매일 코드를 커밋하면 프로필 페이지의 달력이 초록색으로 물드는 기능이 도입되었습니다. 이는 개발자들 사이에서 일종의 게임 피드백처럼 작용하며 꾸준한 코딩을 유도하는 문화가 되었습니다.
    - **개발자의 진짜 이력서:** 경력 기술서 백 줄보다 "내 깃허브 주소 보라"는 말이 통하는 시대가 열렸습니다. 어떤 프로젝트에 참여했고, 코딩 스타일이 어떤지, 다른 개발자들과 어떻게 토론(Issue/PR)하는지가 투명하게 공개되면서 채용 시장의 판도를 바꿨습니다.
    - **비즈니스 모델의 정착:** 개인의 공개 저장소(오픈소스)는 무료로 풀되, 기업이나 팀이 코드를 숨겨두고 쓸 수 있는 '프라이빗 저장소(Private Repository)'를 유료화하면서 강력한 B2S(Business to Software-engineer) 서비스로 자리 잡았습니다.
    
    ## 4. 마이크로소프트(MS) 인수와 엔터프라이즈 서비스로의 진화 (2018~현재)
    
    2018년, **마이크로소프트가 깃허브를 75억 달러(약 8조 원)에 인수**하면서 전환점을 맞이합니다. 당시 개발자들은 "오픈소스의 성지가 대기업의 소유가 된다"며 우려했지만, 결과적으로 MS는 깃허브를 완벽한 종합 개발 플랫폼(DevOps) 서비스로 진화시켰습니다.
    
    - **GitHub Actions:** 코드 저장소 기능에 더해, 코드를 자동으로 테스트하고 서버에 배포까지 해주는 CI/CD(지속적 통합/배포) 자동화 서비스를 내장하여 개발 프로세스를 한 곳으로 통합했습니다.
    - **GitHub Copilot (AI 시대의 도래):** 오픈소스 코드가 모여있는 거대한 데이터베이스를 바탕으로, OpenAI와 협력해 세계 최초의 AI 코딩 어시스턴트인 '코필럿'을 출시했습니다. 현재는 포춘 100대 기업의 90% 이상이 사용할 만큼 전 세계 개발 생산성을 바꾸어 놓은 핵심 유료 구독 서비스가 되었습니다.
    - **종합 워크스페이스화:** 이제는 코드 분석, 보안 취약점 자동 탐지, 클라우드 개발 환경(Codespaces) 제공 등 개발의 시작부터 끝까지 책임지는 거대한 SaaS(Software as a Service) 제품군이 되었습니다.
    
    > 📌 **요약하자면**
    깃허브는 **"개발자들이 편하게 오픈소스 코드를 나누고 토론할 순 없을까?"**라는 아주 순수한 커뮤니티적 고민에서 출발했습니다.

    ## 2. AI 시대의 도래: "형들이 나누던 잡담이 전부 황금 데이터였어?"

    - **API 유료화 선언:** 과거에는 외부 앱이나 크롤러(데이터 수집기)들이 레딧 데이터를 공짜로 퍼갈 수 있었지만, 레딧은 이를 전면 유료화했습니다. 이 과정에서 유저들과 마찰이 있기도 했지만, 결과적으로 레딧의 가장 강력한 고수익 비즈니스 모델(High-margin Business)이 되었습니다.

아 그 뭐라더라. ai한테 데이터 제공하는 기업들을 지칭하는 말이 있었는데… 암튼 토론 데이터가 엄청난 경쟁 우위를 만들었구나. 심지어 ipo한 것도 몰랐네. 미장 했으면 알았을텐데..

- 답변
    
    맞습니다! 그 표현이 생각날 듯 말 듯 하셨을 텐데, 시장에서는 이들을 주로 **'AI 데이터 공급업체(AI Data Providers)'** 또는 데이터가 AI의 핵심 연료라는 뜻에서 **'데이터 마이닝 기업'**, '데이터 라이선서(Data Licensor)'라고 부릅니다. 골드만삭스 같은 곳에서는 AI 벨류체인을 분석할 때 아예 'AI 인프라 및 데이터 스타트업' 섹터로 묶어서 분류하기도 합니다.
    
    미국 주식(미장)을 평소에 유심히 보셨더라도 레딧의 IPO나 깃허브의 수익화 모델은 워낙 소리 없이 강력하게 진행되어서 타이밍을 놓치기 쉽습니다.

    ## 1. 커뮤니티의 '말싸움'이 가장 비싼 데이터가 된 이유
    
    AI 학습 데이터는 크게 두 가지로 나뉩니다. 위키피디아처럼 정제된 '교과서 데이터'와 사람들이 주고받는 '구어체/토론 데이터'입니다.
    
    초기 AI들은 교과서 위주로 배워서 문장은 똑부러지게 썼지만, 인간 특유의 뉘앙스, 유머, 맥락을 이해하는 데 한계가 있었습니다. 레딧의 토론 데이터가 독보적인 경쟁 우위를 가지는 이유는 다음과 같습니다.
    
    - **집단지성 기반의 필터링 (Upvote/Downvote):** 레딧은 좋은 글이나 정답에 가까운 댓글에 유저들이 추천(Upvote)을 눌러 상단으로 올립니다. AI 기업들 입장에서는 "어떤 질문에 대해 인간들이 가장 정답이라고 인정한 답변"을 통째로 솎아내서 학습시키기 최고의 환경인 셈입니다.
    - **살아있는 콘텍스트(Context):** 매일 수백만 명이 트렌드, 정치, 주식, 테크에 대해 끝장 토론을 벌이기 때문에, AI가 '최신 인간 동향'과 '논리적인 반박 흐름'을 배우기에 이보다 좋은 교과서가 없습니다.
    
    ## 2. 알았다면 들어갔을 미장, 레딧(RDDT)의 상장 성적표
    
    실제로 레딧이 2024년 3월에 상장했을 때, 시장의 우려를 깨고 엄청난 랠리를 보여주었습니다.
    
    - 공모가 **34달러**로 시작했던 주가는 상장 첫날에만 48% 폭등했습니다.
    - 이후 구글, OpenAI와의 공식 데이터 라이선스 계약이 연달아 터지고, 광고 효율이 시각적으로 증명되면서 주가가 공모가 대비 몇 배 이상 뛰는 기염을 토하기도 했습니다.
    - 깃허브를 삼킨 마이크로소프트처럼, 레딧 역시 '단순 커뮤니티'가 아니라 'AI 시대의 원유 공급 기지'로 재평가받았기 때문에 가능한 무빙이었습니다.
    
    > 💡 **비즈니스 관점에서의 한 줄 정리**
    과거의 플랫폼 기업들은 유저들의 '체류 시간'을 늘려 **광고**를 보여주는 게 유일한 BM(비즈니스 모델)이었습니다.
    하지만 AI 시대의 플랫폼 기업들은 유저들이 남긴 **'활동 흔적(데이터)' 자체를 빅테크에 가공해서 파는 B2B 데이터 비즈니스**로 패러다임을 완전히 바꾸고 있습니다.

## 3. Astro Nano

https://astro.build/themes/details/astronano/

"복잡한 기능 다 필요 없고, 로딩 속도가 빛보다 빨랐으면 좋겠다" 하시는 분들을 위한 **초경량 극미니멀** 템플릿입니다.

- **스타일:** 군더더기를 완전히 걷어낸 이력서(Resume) + 한 줄 링크 + 미니멀 블로그 형태.
- **SEO / 테크 강점:** 코드가 워낙 가볍고 압축되어 있어서 모바일 환경이나 나쁜 네트워크 환경에서도 구글 검색 로봇에게 압도적인 가산점을 받습니다.
- **적합한 카테고리:** 담백한 일상 에세이, 당뇨 관리 기록, 링크드인 프로필의 확장판.

일단 첫 날의 삽질은 여기까지 하기로 했다. 결정 장애가 왔기 때문이다. 출근을 매우 일찍하는 편이라, 아침에 자기 계발을 할 수 있을 것이라는 생각에 살짝 설레기도 했다. 설레는 마음은 오래 가져가는게 좋을테니, 오늘은 여기까지.

- 토픽 관련
    
    다루고자 하시는 주제의 스펙트럼이 정말 깊고 입체적입니다. 비즈니스와 테크(AX), 거시적 시장(중국, IR)이라는 날카로운 전문 영역이 한 축을 이루고, 당뇨라는 개인적인 헬스케어 서사와 삶을 돌아보는 에세이가 다른 한 축을 단단히 받쳐주고 있네요.
    
    이 6가지 주제는 SEO(검색엔진)와 **AEO/GEO(AI 답변 엔진)** 관점에서 각각 엄청난 무기를 가질 수 있는 완벽한 소스들입니다. 구축하실 홈페이지에서 이 주제들을 어떻게 배치하고 최적화 실험을 하면 좋을지, 마케팅/기술적 관점에서 매칭해 드릴게요.
    
    ## 🎯 주제별 SEO / AEO 최적화 전략 및 배치
    
    ### ① 비즈니스 / IR / 중국 관련 (전문성 & 권위성 축)
    
    - **성격:** 철저하게 AEO/GEO(AI 인용)를 타깃팅하기 좋은 고부가가치 콘텐츠입니다.
    - **전략:** "2026년 중국 제조 공급망의 변화", "스타트업 IR 라운드에서 놓치기 쉬운 지표" 같은 구체적이고 전문적인 키워드를 제목과 서두에 배치합니다.
    - **기술 테스트:** 앞서 말씀드린 JSON-LD 구조화 데이터(Schema Markup)를 이 카테고리에 집중적으로 심어보세요. AI 엔진(Perplexity 등)이 비즈니스나 시장 전망을 답변할 때, 내 글의 통계나 인사이트를 1차 출처로 긁어가서 인용하는 GEO 최적화 실험을 하기에 가장 좋습니다.
    
    ### ② AI 및 AX 관련 (테크 & 아키텍처 축)
    
    - **성격:** 전통적 SEO(구글 검색)와 **AEO** 둘 다 강력하게 작동하는 기술 콘텐츠입니다.
    - **전략:** 단순 트렌드 소개가 아니라, 본인이 직접 n8n, Docker, LLM API 등을 활용해 구축해 본 "실제 워크플로우(Workflow)와 시스템 아키텍처 다이어그램"을 글로 녹여냅니다.
    - **기술 테스트:** 개발자나 기획자들이 구글에 특정 에러나 자동화 구조를 검색할 때 상위 노출되는 전통적 SEO 성능(코드 블록 최적화, 이미지 Alt 태그 최적화)을 테스트하기에 가장 좋습니다.
    
    ### ③ 당뇨 관련 (경험 & 신뢰성 축)
    
    - **성격:** 구글이 가장 까다롭게 평가하는 **YMYL(Your Money or Your Life: 건강/금융 관련 주제)** 영역이자, 인간 고유의 EEAT(경험, 전문성)이 극대화되는 콘텐츠입니다.
    - **전략:** 의학 정보 짜집기가 아니라, 본인이 겪은 **1형 당뇨 관리나 케토산증 응급실 회고 같은 '실제 경험 데이터'** 기반으로 글을 씁니다. 구글의 최신 알고리즘은 AI가 생성한 뻔한 건강 정보보다, 인간이 직접 겪은 날것의 경험(Experience)에 엄청난 검색 가산점을 줍니다.
    - **기술 테스트:** AI가 도저히 흉내 낼 수 없는 '인간의 고유한 경험 데이터'가 검색 엔진 상위 노출에 얼마나 유리하게 작용하는지 체감할 수 있는 좋은 실험 정체성입니다.
    
    ### ④ 에세이 (인간미 & 앵커 축)
    
    - **성격:** 검색 유입보다는 링크드인을 타고 내 홈페이지에 들어온 **사람(투자사, 파트너)들이 나라는 사람의 철학에 매료되게 만드는 앵커(닻) 역할**입니다.
    - **전략:** 러닝/마라톤을 하며 느끼는 한계 돌파의 감각이나 일상의 사색을 담백하게 연재합니다.
    
    ## 🏛️ 이 주제들을 담을 미니멀 홈페이지 구조 제안
    
    6가지나 되기 때문에 대문이 복잡하면 스파게티가 됩니다. Astro 나 Next.js 템플릿을 쓰실 때 카테고리를 딱 **3개의 대분류**로 묶는 것을 추천합니다.
    
    1. **`/biz` (Business & Market):** 비즈니스, IR, 중국 관련 인사이트 (AEO/GEO 집중 타깃)
    2. **`/tech` (AI & Automation):** AX 자동화 아키텍처, 삽질 기록, 개발 테스트 (구글 SEO 집중 타깃)
    3. **`/life` (Life & Essay):** 당뇨 극복기, 러닝 회고, 에세이 (인간적인 신뢰성/EEAT 타깃)
    
    이렇게 도메인 뒤의 경로(Slug) 구조를 깔끔하게 분리해 두면, 구글 로봇이 내 사이트를 크롤링할 때 구조가 명확해서 점수를 아주 잘 줍니다.
    
    ## 🚀 "내가 쓴 글이 AI의 답변이 되는 과정"을 테스트하는 짜릿함
    
    이 홈페이지를 만들면 단순히 글을 쓰는 행위를 넘어, "내가 쓴 글을 ChatGPT나 퍼플렉시티가 어떻게 학습하고 인용하는가?"를 직접 엔지니어링 관점에서 추적할 수 있습니다.
    
    예를 들어, 본인 홈페이지에 본인만의 독창적인 'AX 자동화 로직'이나 '중국 비즈니스 분석법'을 올린 뒤, 일주일 후에 Perplexity에 관련 질문을 던졌을 때 **내 홈페이지 주소가 [출처 1]로 딱 찍히는 순간**의 희열은 노션이나 링크드인에서는 절대 느낄 수 없는 독립 홈페이지족만의 특권입니다.
    
    주제 라인업이 워낙 훌륭해서, 세팅만 해두면 아주 밀도 높은 테스트베드가 될 것 같습니다. 시작해 보셔도 좋겠는데요?
